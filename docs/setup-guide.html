    Das Repository automatisiert nur sichere und reproduzierbare Schritte. Apple-Logins, Lizenzen, biometrische Freigaben, private Schlüssel und macOS-Datenschutzrechte bleiben bewusst manuell. Wenn eine manuelle Aktion eine spätere Bootstrap-Stufe blockiert, hält der Bootstrap direkt dort an, wartet in einem interaktiven Terminal und prüft das Ergebnis vor dem Fortsetzen. Ohne interaktives Terminal beendet er sich mit Exit-Code 2 und nennt den erneut auszuführenden Befehl.

    Diese Schritte schaffen die minimale Umgebung, in der das Repository seinen eigenen Bootstrap übernehmen kann.

    Den Mac initialisieren, dann das Setup anwenden

    Automatisch 
    cd ~/github/phoenix-error/dotfiles
./bootstrap.sh

    ./bootstrap.sh installiert nur Xcode Command Line Tools, Homebrew und mise, verlinkt ~/.zprofile und ~/.zshrc und hört dann auf. Danach neues Terminal öffnen, damit die Shell brew und mise findet. 

    mise run setup

    Meldet ./bootstrap.sh, dass die Shell-Konfiguration nicht verlinkt werden konnte, liegen dort schon handgeschriebene Dateien. Dann stattdessen ~/.local/bin/mise run setup aufrufen. Der Task installiert Homebrew-Pakete, pausiert danach für Git und SSH von Hand, setzt dann Runtimes, globale CLIs, Dotfile-Symlinks, bestätigte macOS-Defaults und nach Möglichkeit die MAS-Apps fort. Editor-Extensions und Direktdownload-Apps gehören nicht dazu.

    Git ist bewusst nicht Teil des Repos. ~/.gitconfig, ~/.config/git/ignore und ~/.ssh/config werden von Hand gesetzt, weil eine verwaltete Git-Konfiguration schon aktiv wäre, bevor der Schlüssel existiert, mit dem sie signiert. Nach dem Brewfile pausiert mise run setup, bis Identität, Ed25519-Schlüssel und ssh -T git@github.com stehen. Schlüssel erzeugen, bei GitHub registrieren und die Verbindung prüfen bleiben manuell. Die GitHub CLI kann später folgen. Private Schlüssel, Hosts und Logins bleiben ausschließlich lokal.

    Git-Identität von Hand setzen

    Bootstrap-Gate 
    git config --global user.name "phoenix-error"
git config --global user.email "42442490+phoenix-error@users.noreply.github.com"
git config --global init.defaultBranch main

    Sobald Homebrew Git installiert hat, pausiert der Bootstrap und wartet auf diese Schritte. Die GitHub-Noreply-Adresse hält die private Adresse aus öffentlichen Commits heraus.

    ~/.ssh/config anlegen

    Manuell 
    mkdir -p ~/.ssh
chmod 700 ~/.ssh
cat > ~/.ssh/config <<'EOF'
Host *
  AddKeysToAgent yes
  UseKeychain yes
  ServerAliveInterval 60
  ServerAliveCountMax 3

Host github.com
  HostName github.com
  User git
  IdentityFile ~/.ssh/id_ed25519
  IdentitiesOnly yes
EOF
chmod 600 ~/.ssh/config

    Ohne diese Datei lädt SSH den Schlüssel nicht aus dem Schlüsselbund und fragt die Passphrase bei jeder Verbindung erneut ab.

    Ed25519-Schlüssel erzeugen und laden

    Manuell 
    ssh-keygen -t ed25519 -C "42442490+phoenix-error@users.noreply.github.com"
ssh-add --apple-use-keychain ~/.ssh/id_ed25519
pbcopy < ~/.ssh/id_ed25519.pub
ls -l ~/.ssh/id_ed25519 ~/.ssh/id_ed25519.pub
ssh-keygen -lf ~/.ssh/id_ed25519.pub

    Eine sichere Passphrase wählen. Den öffentlichen Schlüssel danach in die Zwischenablage kopieren.

    Nur ~/.ssh/id_ed25519.pub darf geteilt werden. ~/.ssh/id_ed25519 ist der private Schlüssel und bleibt auf dem Mac.

    Public Key bei GitHub für Auth und Signing hinterlegen

    Manuell

    Den kopierten Schlüssel unter GitHub SSH and GPG keys zweimal hinzufügen: einmal als Authentication Key und einmal als Signing Key. Nur Authentication reicht nicht für verifizierte Commits.

    GitHub-SSH-Verbindung prüfen

    Bootstrap-Gate 
    ssh -T git@github.com

    Den angezeigten Host-Fingerprint mit GitHubs veröffentlichten Fingerprints vergleichen. Erst nach successfully authenticated im Bootstrap-Terminal Return drücken. Der Bootstrap prüft Identität, Schlüsseldateien und diesen SSH-Test, bevor er fortsetzt.

    Commit-Signing aktivieren, erst nach dem Schlüssel

    Manuell 
    printf '%s %s\n' \
  "$(git config --global --get user.email)" \
  "$(awk 'NR == 1 { print $1 " " $2 }' ~/.ssh/id_ed25519.pub)" \
  > ~/.ssh/allowed_signers
chmod 644 ~/.ssh/allowed_signers
git config --global gpg.format ssh
git config --global user.signingkey ~/.ssh/id_ed25519.pub
git config --global gpg.ssh.allowedSignersFile ~/.ssh/allowed_signers
git config --global commit.gpgsign true

    Nicht früher ausführen. Ist commit.gpgsign aktiv, bevor ~/.ssh/id_ed25519 existiert, scheitert jeder Commit mit fatal: failed to write commit object.

    Lokalen Signing-Status prüfen

    Prüfung 
    ls -l ~/.ssh/id_ed25519 ~/.ssh/id_ed25519.pub ~/.ssh/allowed_signers
ssh-keygen -lf ~/.ssh/id_ed25519.pub
git config --global --get gpg.format
git config --global --get commit.gpgsign
git log --show-signature -1

    Erwartet werden ssh, true und nach dem ersten Push ein von GitHub als Verified angezeigter Commit.

    Cursor-Extensions optional von VS Code spiegeln

    Optional

    Cursor hat kein Microsoft Settings Sync. Wenn Cursor denselben Extension-Satz wie VS Code bekommen soll, einen Claude Agent mit dem Prompt unten spawnen. Er installiert alles, was Cursor laden kann, und überspringt IDs, die nur im Visual Studio Marketplace existieren, zum Beispiel Modernized. 

    Mirror my currently installed VS Code extensions into Cursor.

1. Run `code --list-extensions` and capture every installed extension ID.
2. For each ID, try `cursor --install-extension <id>`.
3. Skip extensions Cursor cannot install. Known cases:
   - `sukarth.vscode-modernized` (Visual Studio Marketplace only)
   - `ms-python.vscode-pylance` (Microsoft license; install `anysphere.cursorpyright` instead)
4. If VS Code has Pylance, ensure Cursor has `anysphere.cursorpyright`.
5. Report three lists: installed, already present, and failed with the exact error.

Do not change VS Code. Do not edit settings.json. Only install Cursor extensions.

    Definition of done

    Der Mac ist erst fertig, wenn er einen Reboot überlebt.

    Ein grüner Doctor ist die technische Basis. Die echte Abnahme sind zwei erfolgreiche native Builds, funktionierende Agent-Teams, überprüfte Rechte und ein identischer Zustand nach dem Neustart.
